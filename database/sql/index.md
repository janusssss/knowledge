# 问题
## 回表
回表（Lookback）是指在使用**非聚簇索引（二级索引）**查询时，如果索引无法覆盖所有需要的列，数据库需要通过索引中存储的**主键值**，再回到**聚簇索引（主键索引）**中查找完整行数据的过程。

```sql
-- 表结构: id(PK), name, age, email
-- 有非聚簇索引 idx_name(name)

SELECT * FROM users WHERE name = 'Alice';
```

**执行流程：**
1. 在 `idx_name` 索引中找到 `name = 'Alice'` 的记录，得到对应的 **主键 id**
2. 用该 id 回到聚簇索引，查找完整行数据（获取 age、email 等列）

- 非聚簇索引的叶子节点只存储**索引列 + 主键**，不包含

## 索引的设置
1. 基本原则：配合查询方式建索引

先看 SQL 的 **WHERE 条件、JOIN 字段、ORDER BY、GROUP BY** 用到哪些列，为这些列建立索引。索引是为查询服务的，不是越多越好。

2. 哪些字段适合建索引（优先系数高到低）

- **频繁出现在 WHERE / JOIN 条件的列**（高区分度，比如 user_id）
- **高区分度 / 高选择性字段**：性别、状态这类只有少数取值的列区分度低，效果差
- **ORDER BY / GROUP BY 的列**：避免 filesort、临时表
- **覆盖索引**：把要查询的列也加进联合索引，避免回表

3. 建索引的方式

- **单列索引**：简单场景
- **联合索引（复合索引）**：遵循**最左前缀原则**
  ```sql
  CREATE INDEX idx_uid_status ON orders(user_id, status);
  -- 生效: WHERE user_id=1; WHERE user_id=1 AND status=2
  -- 不生效: WHERE status=2  （跳过了最左列）
  ```
  - 区分度高的放前面
  - 联合索引本身可以替代多个单列索引

- **唯一索引**：业务上不允许重复的列（如 email）

4. 什么情况不该建（体现功力）

- 区分度极低的列（性别、is_deleted 这种 0/1）
- 频繁 UPDATE / INSERT 的表：索引越多写入越慢、占空间越大
- 大数据量列做索引（如超长 VARCHAR）→ 考虑**前缀索引**
