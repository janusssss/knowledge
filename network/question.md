# HTTP1.0和HTTP2.0的区别
**HTTP/2.0 的核心是对性能的全面革新，而 HTTP/1.0 的设计则更像一个基础版本**。它们之间最大的不同在于，HTTP/2.0 通过引入**二进制分帧**和**多路复用**，解决了 HTTP/1.0 最致命的性能瓶颈——**队头阻塞**。

我把它们的核心区别整理成了下面这个表格，这样看起来会更清楚：

| 特性 | HTTP/1.0 | HTTP/2.0 | 关键影响 |
| :--- | :--- | :--- | :--- |
| **连接方式** | **短连接**：每次请求都需要新建一个TCP连接，请求完成后立即断开。 | **长连接**：所有请求共享一个TCP连接，可以复用。 | HTTP/2.0省去了反复建立连接的开销，显著提升了效率。 |
| **数据传输格式** | **文本格式**：基于文本解析，传输内容为人可读的字符串。 | **二进制格式**：将数据分割为更小的二进制帧进行传输。 | HTTP/2.0的二进制格式解析更高效、更健壮，是实现多路复用的基础。 |
| **请求处理方式** | **队头阻塞**：在一个连接中，请求必须按顺序排队处理，前一个请求未完成会阻塞后续所有请求。 | **多路复用**：可以在同一个连接中同时处理多个请求和响应，互不干扰。 | **这是最核心的差异**。HTTP/2.0通过“多路复用”彻底解决了HTTP/1.0的队头阻塞问题，极大提升了页面加载速度。 |
| **Header压缩** | **不压缩**：每次请求都会重复发送完整的头部信息，开销大。 | **HPACK压缩**：使用HPACK算法压缩头部，减少传输数据量。 | HTTP/2.0有效降低了网络开销，尤其对头部信息庞大的请求效果显著。 |
| **服务器推送** | **不支持**：客户端必须主动请求所有资源。 | **支持**：服务器可以主动向客户端推送它可能需要的资源。 | HTTP/2.0的这个特性可以进一步优化加载性能，减少客户端请求的等待时间。 |

### 📝 补充说明：HTTP/1.0 与 1.1

值得一提的是，在实际应用中，**HTTP/1.1 是对 HTTP/1.0 的重要改进版本**。它默认启用了长连接（`keep-alive`），允许复用TCP连接，一定程度缓解了性能问题。你提到的“HTTP1.0”通常指的就是这个更古老的版本，而“HTTP2.0”则是在1.1基础上的又一次飞跃。
